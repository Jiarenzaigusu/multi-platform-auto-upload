## Bug 修复：首次打包后启动即 UnboundLocalError

打包 .exe 后连接即弹"cannot access local variable 'disconnect_and_exit'"，traceback 指向 `desktop.py:901` 的 `theme.danger_button(...)` 调用。

根因：经典 Python 作用域坑。`_run_status_window` 函数体内任何位置出现对 `disconnect_and_exit` 的 `def` 定义，CPython 就会把 `disconnect_and_exit` 标记为**整个函数**的局部变量。我最初把按钮 UI（首次引用 `disconnect_and_exit` 作为 command）放在了 `def disconnect_and_exit` **之前**，运行时执行到该行时 `disconnect_and_exit` 作为局部变量尚未赋值，直接 `UnboundLocalError`。

修复：把 `def disconnect_and_exit() -> None: ...` 整体挪到按钮 UI（`account_actions` frame + `theme.danger_button(...)`）**之前**定义，保证引用时名字已绑定。当前顺序：
1. `update_status_label.pack(...)`
2. `def disconnect_and_exit() -> None: ...`  ← 先定义
3. `account_actions = tk.Frame(...)` + `theme.danger_button(..., disconnect_and_exit, side="left")` ← 后引用

教训：函数体内给 tk.Button / 回调命令传嵌套函数时，被引用的嵌套函数必须先 `def`，否则会 UnboundLocalError（即使逻辑上后续会定义）。

验证：两个文件 `py_compile` 通过；逻辑顺序确认 def 在引用之前。需在 Windows 上重新运行 `deploy/windows/build-mpau-agent.ps1` 重新打包验证。

## 复查又修一处：跨线程 tk 调用隐患

复查时发现 `disconnect_and_exit` 的 worker 线程里原写法 `root.after(0, lambda: (application.stop(), root.destroy()))` 是**跨线程调用 tkinter**——tkinter 不允许非主线程碰 Tk 对象，点击按钮后很可能抛 `RuntimeError: main thread is not in main loop`。

修复：worker 线程只做 `_revoke_pairing(...)` + `application.stop()`（`stop()` 仅 `self.stopping = True` 布尔赋值，线程安全）+ `enqueue("application-stopped")`（`queue.Queue.put`，线程安全）；由主线程 `drain_queue` 收到 `application-stopped` 后 `root.destroy()`。这样所有 Tk 操作都回到主线程，复用项目已有的 enqueue/drain_queue 事件模型。
