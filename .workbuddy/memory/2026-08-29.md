## 排查 MPAU-Agent「无法连接 Windows 助手本机上传服务」报错

### 结论：不是网络连不上，是 CORS 预检失败被前端误报

**定位路径**
- 报错文本位于 `webapp/frontend/src/App.vue:1199`（`uploadFileToAgent` 内 fetch 失败 3 次后抛出）
- 本地上传地址由后端硬编码：`webapp/api/agent_tasks.py:257` → `http://127.0.0.1:48765/v1/upload`
- 该端口由 `local_agent/local_upload.py:165` 的 `LocalUploadServer` 监听

**根因（已实测确认）**
`local_agent/local_upload.py` 的 `_json()` 仅在显式传入 `origin` 时才写 CORS 头：
```python
def _json(self, status, body, *, origin: str = "") -> None:
    ...
    if origin:
        self._cors_headers(origin)
```
而 `do_OPTIONS` / `do_POST` 的所有错误分支调用时都是 `self._json(status, {...})`，**不传 origin** → 响应无
`Access-Control-Allow-Origin`、也无 `Access-Control-Allow-Private-Network`。
页面在公网 `175.27.255.46:8788`、请求打到 `127.0.0.1:48765`，属跨域 + 公网→私网（PNA），
预检响应缺 CORS 头时浏览器直接判定失败，`fetch()` 抛 `TypeError: Failed to fetch`，
前端统一 catch → 误导为「无法连接助手」。

**触发时机**：日志中 15:46–15:49 云端大量 `HTTP 502`，本地 `authorize_local_upload` 向云端校验
ticket 拿到 502 → 返回无 CORS 头的 502 → 预检失败。云端后续已恢复（连续 6 次探测均 401 正常）。

### 实测数据（本机）
- 端口：`netstat` 显示 `127.0.0.1:48765 LISTENING`，PID 191256
- 进程：`MPAU-Agent.exe` 存活，约 45 MB
- 本地服务：`curl -X POST` 返回 `{"detail":"本机上传请求无效"}`（业务正常，服务在工作）
- 模拟预检：`curl -X OPTIONS ... -H "Origin: http://175.27.255.46:8788"` → `422`，响应头**无任何 CORS 字段**

## 排查 MPAU-Agent「首次配对后点执行任务 → 助手静默退出、心跳租约失效」

### 结论：任务线程由托盘 setup() 回调启动，托盘未就绪时 worker 从未启动，主流程直接 return 使进程退出

**关键代码链（local_agent/desktop.py）**
- `run():1251-1261` — worker 线程 `daemon=True`，但**不在此时 start**，仅创建
- `run():1259-1261` — `start_worker_after_tray_ready()` 把 `worker.start()` 作为 `on_ready` 传给 `_run_tray`
- `_run_tray.setup():554-571` — **顺序是关键**：先 `_icon.visible = True` 并校验 → 再 `on_ready()`（启动 worker）→ 再 `_start_background_update_checks`
  → 校验失败/抛异常时 `application.stop()` + `_icon.stop()`，`on_ready()` 根本没执行
- `_run_tray:607-610` — `icon.run()` 返回后 `if tray_failure: raise` / `if not application.stopping: raise RuntimeError("Windows 托盘循环意外结束")`
- `_run_tray:611-622` — except 分支 `_show_fatal_error()` 后 `return "tray-failed"`
- **`run():1272-1279`** — `if tray_outcome == "tray-failed":` 且 `worker_started` **未置位** → 不 join，直接 `return` → 主线程结束 → daemon 线程被杀 → **进程静默退出**

这是唯一「无任何提示、直接退出」的路径，且完全符合「首次退出 / 第二次正常」：
安装包 `deploy/windows/mpau-agent-installer.iss:43-44` 的 `[Run] ... Flags: nowait postinstall`
会在装完时自动拉起助手，此时托盘区最不可能就绪（Explorer 未刷新），最易触发。

**为什么用户感觉是「点执行任务时退出」**
配对弹窗在托盘**之前**，配对成功提示是「本地执行助手已连接，以后只需打开发布台网页」——用户以为已连接；
实际进程随后就退出了。等用户在网页点「执行任务」，任务入队无人领取，
45s 后 `webapp/api/agent_tasks.py:625 reap_expired_jobs()` 回收，
error=`本地代理心跳租约已过期` → 前端显示心跳租约失效。
**40 秒这个数字对应** `local_agent/main.py:294` 的 `elapsed >= self.lease_seconds - 5`（45-5=40）。

### 相关参数
- `main.py:132` `lease_seconds = 45.0`（服务端 `agent_tasks.py:51` 同为 45，min 30）
- 心跳周期 10s（`main.py:428` `future.result(timeout=10)`）
- 服务端 `_offline_after_seconds() = 25.0`：代理 25s 未续约即从 `_agents` 剔除
- **`client.py:46` `request_json` 默认 `timeout=45`**，心跳也用它 —— 一次慢心跳即可吃掉整个租约；应单独设短超时（建议 5-8s）

### 其他已确认的放大/次生缺陷
1. **409 被当成终态**：`agent.py:481-483` 把 `RuntimeError` 映射成 `HTTP 409`；
   `main.py:293` 把 `{401,403,404,409}` 视为 terminal → 直接 `AgentLeaseLostError` 取消任务。
   服务端代理掉线（25s）后心跳必返 409 → 任务被误杀，而非重试。
2. **`main.py:426-443` 循环缺陷**：`AgentJobCancelledError` / `AgentLeaseLostError` 被 catch 后只做
   `self.runner.cancel(job_id)`，**循环不 break**，会继续 `future.result(timeout=10)` 反复重试。
3. **`_start_wake_listener` 端口 48766 被绑定两次**：`_connect_with_status_window:1186` 与
   `_run_tray:605` 各起一个；前者 `finally` 里 `listener.join(timeout=1)` 可能超时，
   Windows 下 `SO_REUSEADDR` 允许重复绑定 → 存在陈旧监听实例。
4. **心跳与业务共用 `self.opener`**：urllib opener 多线程共用，下载与心跳并发时无独立超时控制。
